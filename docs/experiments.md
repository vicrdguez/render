# Protocol-first experiments

Experiments use the existing Ledger command/artifact and Engine role interfaces, not a delivery Contract. They never create adoption, publication or source-copy authority. A coordinator's observable-uncertainty escalation remains a retained suggestion: the caller must explicitly schedule the experiment. There is no automatic product-choice approval.

## Start a round

1. Retain human Ground with `saveDocument`, then a JSON protocol as another immutable document revision. The protocol has `schema:1`, `ground` (exact revision), `question`, `hypothesis`, `falsifier`, `decisionRule`, nonempty `controls`, `fixtures`, `failureCases`, and `retainedOutputs` arrays. `source` pins `{repository,commit}`; `candidates` names one to four independent candidates (lowercase names).
2. Preregister `budget:{maxCommands,timeoutMs}` per candidate and parent, and `profile:{image,exclusions,maxBytes,maxEntries}`. The image is an immutable locally installed Linux image ID; `.git` is explicitly excluded. Experiment retained source is bounded to 1 MiB per snapshot, 10,000 entries, 32 commands and 300,000 ms per command at most. The ordinary existing container CPU, memory, PID and output bounds also apply. These are collection/execution bounds, not an aggregate writable-disk quota.
3. Configure Engine with `experiments:{root,repositories}` plus its ordinary pinned provider/family configuration. No host credentials or host shell become candidate tools. The installed image must contain the tools required by the protocol; missing tools remain execution failures, not host fallbacks.
4. Use `assignTask` with `delivery:false`, an ordinary explicit packet, role `experiment-candidate`, execution `linux-writer`, and `experiment:{protocol:<revision>,candidate:<name>}`. Each protocol/name has one assignment identity. Different candidates get fresh conversations and separate writers. No checkpoint UI or downstream delivery stage is needed.
5. Each candidate uses `experiment_run({argv})` in its own `/workspace`. Calls are serialized by refusal of concurrent admission, bounded by the preregistration and journaled before dispatch. An interrupted command is unsafe to replay. Ordinary bridge networking can reach host/LAN/tailnet services; this is not route confinement.
6. `submit_role_result` seals the whole environment, roots exact literal source through Effects, and retains original base/fixtures, collected source, scope, protocol digest and raw execution results in SQLite before accepting the model report. Reports use `schema:1`, `protocol`, `outcome` (`positive`, `negative`, `inconclusive`, `deviation`), `summary`, `measurements:[{name,value,unit}]`, `failures:[]`, and nonempty `limits`. Captured runner outputs and model interpretation are distinct evidence.
7. Only after every candidate has submitted sealed evidence and released its confirmed-quiescent slot can an `experiment-parent` assignment use `experiment:{protocol:<same revision>,candidate:null}`. It gets sealed candidate sources at read-only `/candidates/<name>` mounts and separate writable `/workspace` scratch for independent reruns. The same tool/seal/report path retains comparison evidence. Parent context is fresh; it receives no candidate private conversation or packet.

Criteria corrections or candidate repairs require a new protocol revision/round. Saving a newer document revision never changes an existing assignment's exact protocol ref. Completed originals and negative/inconclusive reports remain historical. Kernel refuses delivery mode, different-role adoption, duplicate round identities and parent comparison before complete candidate evidence.

## Retention, restart and blockage

`artifact(read)` and scoped history/export retain exact protocol, packet, source/fixture snapshots, raw observations and reports. Disposable environments may be removed only after those materials are retained. SQLite export contains source bytes, not merely an unrooted working path. Source Git remains separately rooted for actual comparison execution. Missing/corrupt material blocks reliance with an exact reference; no newer candidate is substituted.

A same-store restart fences the old executor. Already sealed source can finish the interrupted report submission under current authority without replaying candidate execution. Engine first reconciles the original recorded container identity, even when the current executor epoch differs. Before sealing, uncertain interrupted execution stays blocked and the original container is stopped/reconciled; a new round is required for changed criteria or corrected candidates. Stop uncertainty retains execution capacity. Cancellation aborts the role and fences tools before releasing capacity only after the original environment is confirmed stopped and admitted work has settled. Neither a blocked label nor a timeout proves death.

The implementation has no automatic environment-deletion command. Fixture cleanup is deliberately external to retained evidence. Disaster recovery, machine migration and off-host protection are not introduced.

## Verification and limits

Preimplementation failure cases are in `verification/protocol-experiments-failure-cases.md`. `npm run verify:protocol-experiments` selects protocol legality, actual read-only Linux mounts/scratch, a standalone disproved-favorite journey, and SIGKILL around report commit. The journey uses a scripted provider, not a live model judgment trial. `npm run verify:experiment-crash` supports the existing separate `RENDER_V3_REPETITIONS=2` extended count. Ordinary source-root/quiescence, authority, history and role-continuation rows remain cumulative supporting checks. Full-product checkpoint/adoption/publication journeys and full V9 load remain later owners' obligations, not claims of this experiment path.

# Rubric (the picker's tool; candidates never see it)

Score each criterion 1 to 5 with quoted evidence.

1. **The walk is real.** Every commit names its trigger, reads, writes, order, and rerun result. An engineer could build the workflow from it without inventing a step. Conversations, owners, roles, and tools are named. The W1 evidence chain is shown link by link, or its break is located.
2. **Legal on pi-durable.** No table read after a table write, `submit(tx, draft)` before the first table write, task and conversation ownership that exists, real symbol names. Check at least three load-bearing claims against source. A probe that ran counts for more than a citation.
3. **Failure paths.** The stale answer, the crash between commits, the agent that stops without handing off, the abort with an open decision, the repeated outside effect, the resent answer, the week-long stop, and the old timer. Each is handled or honestly marked as unhandled.
4. **Respects the rulings and the rule.** Annotation gets an honest pass or fail per check, not a result picked in advance. Its shape matches "the core stores, the workflow gives meaning". `role()` stays in the standard library and stays small. Nothing enters the core without the five checks.
5. **Findings a maintainer can act on.** Each item in "What fell short" is specific, tied to a commit, has the smallest fix, and names the right home. Real problems in `docs/core` are found, not invented.
6. **Candor and evidence.** Labels are used correctly. "Not verified" is complete. Nothing is claimed as run that was only read.

Then answer:

- Which candidate is the best base for the next version of `docs/core`?
- Which one or two ideas from each other candidate are worth porting?
- Where do candidates disagree on a fact, and who is right?
- What did every candidate miss?

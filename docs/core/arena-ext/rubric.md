# Rubric (the picker's tool; candidates never see it)

Score each criterion 1 to 5 with quoted evidence.

1. **The extension is the unit, and the model stays small.** An extension that is not a workflow is bound, selected, given options, and reaches agents without borrowing a workflow concept. What makes a workflow a workflow is one stated thing. The host still knows no particular extension. The three ways for an agent to get an extension are compared on evidence.
2. **Legal on pi-durable.** Claims about extension selection, stored names, compaction, ownership, and the order inside a commit hold. Check at least three load-bearing claims against source. A probe that ran counts for more than a citation.
3. **The extension script holds.** Steps 1 to 6: the reviewer cannot search, the API key has a stated home and a stated exposure, an extension added during running work reaches a stated set of conversations, Q's agent cannot search until the owner adds it, and a server without the code still opens both projects.
4. **Lane gets an honest verdict.** Each of the nine checks has a pass or a fail with evidence. "No lane" is compared fairly. The recommendation follows from the checks, not from the owner's interest in the idea. The shape is the smallest that does the job.
5. **The lane walk holds.** Steps 7 to 12 with their commits: two items that need the implementer at once, compaction and what it loses, a failed run and a restart with a worker out, a steer, and a fresh lane. W1's chain of evidence holds or its break is located.
6. **Candor and evidence.** Labels are used correctly. "Not verified" is complete. Nothing is claimed as run that was only read. The design adds nothing the rulings did not ask for.

Then answer:

- Which candidate is the best base for the next version of `docs/core`?
- Which one or two ideas from each other candidate are worth porting?
- Where do candidates disagree on a fact, and who is right?
- What did every candidate miss?

# Unit 2: the host layer, the protocol, and the `tau` command

| Where | Readings | Taken | Why |
| --- | --- | --- | --- |
| [Protocol](../protocol.md), "refuses an unexpected `Host`" | Check the host name and port, the host name alone, or nothing. | The host name alone. `127.0.0.1`, `localhost`, `[::1]`, and the names in `ServerOptions.allowedHosts` pass, on any port. | The check stops a page that rebinds its own name to loopback. An SSH tunnel on another local port sends another port, and a proxy such as Tailscale Serve sends its own name. So the port carries no protection, and a proxy's name must be configurable. |
| [Protocol](../protocol.md), "refuses a request with another site's `Origin`" | Compare `Origin` with `Host`, or with the allowed names. | An `Origin` must name an allowed host name. No `Origin` passes. | A proxy may rewrite `Host` while the browser keeps its own `Origin`. A CLI sends no `Origin`. |
| The code for a refused `Host` or `Origin` | The design names none. | `unauthorized`, 401. | The check decides who may call, as the token does. A client cannot fix it by sending the body again. |
| The order of the checks | Token first, or `unknown_call` first. | `Host` and `Origin`, then `pair`, then the token, then `unknown_call`, then the body. | `spikes/wire.mjs` checks the token before the call name. Discovery with `POST /v1/` then needs a token, which every client has. |
| An empty body | Read it as `{}`, or refuse it. | `bad_request`. | [Protocol](../protocol.md) says the body is one JSON object. |
| The `unknown` code | The design names `storage_failed` only. | Unexpected errors answer `unknown` with `storage_failed`, at 500. Each paged call checks its cursor payload first. pi-durable's invalid-cursor `StorageRequestError` becomes `bad_cursor`, at 400. Other storage errors stay unknown. | Bad input is a known refusal. A real storage failure cannot be called a refusal. An HTTP test supplies rejecting Storage through `ServerOptions.storage`. |
| A second server on the same home | The store lock alone, or a check on the home as well. | Validate device configuration first. Each store takes its SQLite lock before open. Then check that no live server answers on `admin.sock`. A socket that a killed server left is removed. | The sequential second-server and process-death tests pass. Simultaneous first starts on an empty home remain unproved. The socket check alone does not guarantee exclusion in that case. |
| The lock file | The design says a lock file beside the store. | `projects/<project>/store.lock`, held by an open `BEGIN EXCLUSIVE` as `candidate-2/probe/lock.test.mjs` probed. | The kernel drops it when the process dies. |
| Where a skipped store is reported | A new field in the `projects` result, the server's log, or the `Server` object. | `Server.skipped`, which `tau` prints at start. | The wire stays as [Protocol](../protocol.md) fixes it. A store with no `Project` is a crash the resent `bind` repairs, and a client that resends sees it then. |
| `bind` and extension names | Refuse a name the server lacks, or record it. | Record it in `missing`. The schema checks only that each name is a string. | [Extensions](../extensions.md), and the coordinator's row. |
| `setOptions` for an extension the project does not list, or the server lacks | `bad_request`, `bad_options`, or `extension_not_loaded`. | `extension_not_loaded`. | The extension is not loaded in that project. The code already exists. |
| `setOptions` for an extension with no options | Treat it as an empty closed schema, or refuse. | `bad_options`, with one error at the path `""`. | It is the call's own refusal, and the client shows its errors. |
| Pending pairing codes | Store them, or keep them in memory. | Memory only, as hashes. A restart cancels them. | A code lives ten minutes and is good once. The owner runs the command again. |
| A pairing code | The design gives 8 characters and the example `K7QM-3XRT`. | 8 characters of Crockford's base 32, shown as `XXXX-XXXX`. Case, dashes, and spaces are ignored when it comes back. | 40 random bits, no ambiguous letters, and easy to type on a phone. |
| The admin socket's messages | The design names the three commands only. | One JSON line each way. A request is `{ command, device? }`. A reply is `{ code, expiresAt }`, `{ devices }`, `{ done: true }`, or `{ error }`. Both sides check their message with pi-schema. | The socket is private between `tau` and its own server. An `error` is printed by the command. A device name that exists, or existed, cannot be paired again. A second revoke is `done`. |
| `startServer` | The sketch passed a `Context`. | No `Context`. The server runs its work under `BACKGROUND_CONTEXT`, and `close()` ends it. | [Host](../host.md) says the host runs the work under its own context, so that a client's disconnect ends only its watch. |
| The module map's keys | Derive them from `extension.name`, or check them. | `startServer` refuses a key that differs from its module's `extension.name`. | The kickoff starts the map as `{}`, keyed by name. |
| The `Project` document | The design names it and gives no kind. | A session document of kind `tau.project`. | The store took `tau.decision.*` and `tau.event.log`. |
| `input` with no `whenBusy` | Require it, as candidate 2 did. Make it optional, as candidate 1 did. | Optional. With none, pi-durable's own default applies: a busy conversation queues the input as a follow-up. | [Host](../host.md) does not settle it. `SubmissionDraft` makes it optional, and pi-durable 1.5.2 treats every value but `steer` as `followUp` (`dist/harness/submissions.js:232`). A test reads the queued item's mode. |
| `create` with a model the server lacks | `bad_request`, or `unknown_model`. | `unknown_model`, 409. | The design names that code for `setModel`, and the body itself fits the call. |
| `create` for a workflow name | The design names `not_a_workflow` only. | A name the project does not list, or one without `entry`, is `not_a_workflow`. A listed name the server has no code for is `extension_not_loaded`. | The first two are not workflows of that project. The last one is, but its code is missing. |
| The working directory against a workflow's `entry` | `cwd` wins, as the sketch's comment asked. Or `entry` wins, as [Host](../host.md) writes it. | `configure(tx, id, { cwd, ...entry })`, as written. | The design gives the literal shape, so I copied it. No workflow sets `cwd` today. |
| `setModel`'s `thinkingLevel` | Any string, the seven levels of pi-ai, or the levels the model supports. | The seven levels of pi-ai 1.5.2's `ModelThinkingLevel`. Another string is `bad_request`. | pi-durable clamps a level the model lacks. The schema keeps a typo from being stored. |
| `limit` on a page | A cap, as candidate 1 had, or none. | No cap. The default is 50, the size of a view's first window. | The verdict rejected the invented cap. |
| `conversations` and the event log | Fetch one more row when the log is on the page, or return a page one short. | One short. `next` still pages on. | A page is `{ items, next? }` and only a missing `next` ends it. The log is one conversation. |
| `conversations`, the state | The design names idle, running, and failed. | `running` while `pi.live` has a run, else `failed` while it has a `runFailure`, else `idle`. | These are the two fields of `pi.live` that [Host](../host.md) names. |
| `conversations`, the owner | Reduce it to a conversation ID, or pass it on. | pi-durable's `ConversationRecord.owner`, `{ conversationId, taskId }`, when it has one. | The verdict prefers the substrate's shape. |
| `history` with a cursor and bounds | Let the body's bounds win, or the cursor's. | The cursor's. A body bound that differs from the cursor's is `bad_cursor`. | [Protocol](../protocol.md) says the cursor carries its own bounds. |
| A cursor | The design says base64url of JSON with the query and pi-durable's cursor. | `{ call, project, query, position }`. Closed per-call schemas check the query, each record ID, scan order, and the per-kind fault positions. History checks the position's order against its query. | The outer envelope alone was not enough. Invalid inner positions must be `bad_cursor`, not unknown storage failures. Tests check malformed payloads and a usable session afterwards. |
| `decision`, the `then` field | The task's record, its outcome, or its state. | The task's `state`, as pi-durable 1.5.2 shapes it, when the decision is answered. | [Protocol](../protocol.md) says `then` is the state of the task. |
| A decision ID in a body | A pattern in the schema, or any string. | Any string. One that names nothing is `unknown_decision`. | The store checks the ID. A malformed ID names no decision. |
| `faults` paging | Keep an offset in a mutable page, or anchor the continuation to a record. | Scan pages of 100 per kind, newest first. After a returned fault, store `{ after: task.id, order: "descending" }`, pi-durable 1.5.2's record cursor. An exhausted kind is `null`. | An offset repeated records when a new fault arrived. Task identity stays fixed across inserts and restart. The regression inserts a third fault after reading the first page, then restarts before continuing. |
| A stream that cannot go on | The design names `failed` as an end reason. | A store watch that fails, or that ends other than by a stop, ends the stream with `failed`. A write cut after 60 seconds destroys the socket and sends no `end`, because nothing more can be written. | A client sees a cut with no `end` and opens the watch again, as [Protocol](../protocol.md) says. |
| A heartbeat | Any line that starts with `:`. | `:` and a blank line, 15 seconds after the last write. | The smallest comment line. |
| Biome's `noThenProperty` | Turn it off for the package, or rename. | A `biome.json` in `packages/host` that turns it off there, as the store did. | `then` is a locked field of a decision draft and of the `decision` result. |
| `tau` and model logins | Use pi's compatible lock, or never write back. | `$PI_CODING_AGENT_DIR/auth.json`, else `~/.pi/agent/auth.json`, through a pi-ai `CredentialStore`. `proper-lockfile` 4.1.2 locks the resolved file for each read and the entire read, refresh, write. It uses pi's 30-second stale setting, checks a compromised lock before writing, and releases in `finally`. | The earlier unlocked rename could delete another provider's login permanently. A later refresh cannot repair that. The lock and direct write match pi's `FileAuthStorageBackend`. Tests hold a refresh callback, check the same lock through a symlink, and preserve a concurrent login and logout. No live provider refresh was run. |
| `tau` and the execution environment | Pass none, or a `NodeExecutionEnv`. | A `NodeExecutionEnv` in the conversation's `cwd`, or in the server's working directory when a conversation has none. | Every conversation the host creates has the project's `workdir`. A workflow's helper conversation may not. This is pi-durable's ordinary `HarnessOptions.env`, not sandboxing. |
| Revocation after a failed write | Publish a dirty in-memory mark as success on retry, or persist it again. | Every revoke persists before it acknowledges, including an already marked record. Stream attachment rechecks the token after opening the watch and before piping. | A retry must survive restart. A pending request must not acquire an unbounded stream after revocation. Tests force a real temporary-file write failure and pause an HTTP body. |
| Failed revoke state | Leave the device marked in memory, or restore its prior state when persistence fails. | Restore the prior `revokedAt` and return the write error. The device stays paired in memory, the list, and the saved file until a revoke succeeds. | A failed command must not refuse new calls while its existing stream keeps receiving data. A real write failure test checks calls, the list, and another stream update. |
| Revoke retry after rollback | End streams after a failed attempt, or only after persistence succeeds. | Keep streams open after the failure. A successful retry refuses calls and ends the stream with `revoked`. Restart still refuses the token. | The owner sees the error and can retry. The test checks the successful retry and restarts the server. |
| Start order | Validate device configuration before or after opening projects. | Read and check `devices.json` before opening or resuming any project. Install coding tools and listed extensions before resume. | A due timer must not run when configuration refuses start. The test reopens with the extension absent to inspect that no wake entry landed, then restores the extension and observes its wake. A synchronous resume-before-install mutation may be scheduling-equivalent in pi 1.5.2; this test does not prove it distinguishable. |
| Annotation ranges | Restrict the HTTP shape to nonnegative integers, or accept numbers and let `answer` decide. | Accept numbers. The store returns `bad_annotation` at 409 for negative, fractional, or out-of-bounds ranges. | The answer table owns that refusal. Tests check no entry or answer is written. |
| `tau` listen port | Bind the default in every command test, or expose an ordinary port option. | `--port PORT` accepts 0 through 65535. With no flag, the command passes 6283. Lifecycle tests use 0 and read the chosen address from stdout. | Concurrent gates must not fight for a user's default port. A parser assertion checks 6283 without binding it. |
| Host Storage | Hard-code SQLite, or allow an ordinary Storage opener. | `ServerOptions.storage(file)` defaults to `openNodeSqliteStorage`. Every project still takes its lock first. | The HTTP failure test supplies real SQLite with a rejecting Storage method. This is a dependency seam, not a fault route or production test flag. |
| Stream window evidence | Infer the numbers from a broad gap test, or assert the thresholds. | A held real tool appends entries. The first window has 50, grows to 100 without a drop, and the 101st drops back to 50 with the correct `before`. | The old gap test passed with 25 and 50. The new test rejects that mutation. The Storage test rejects changing unknown's HTTP status to 200. |
| Input transcript order | Treat object key order as irrelevant, or match the sample bytes where possible. | Serialize the submission's `id` first, followed by pi-durable's remaining fields. | The input transcript shows this order. IDs still come from the real run and are not fixed fixtures. |
| `tau` and a proxy's host name | No way to set it, an environment variable, or a flag. | `tau --allow-host NAME`, which may repeat. With none, only the loopback names pass. | A proxy that keeps the device's `Host`, such as Caddy, would be refused otherwise, and the owner could not reach the server from a phone. Candidate 1 proposed the same flag, and the verdict called it an implementation choice. |
| `tau` and a signal | Exit at once, or close first. | The first `SIGINT` or `SIGTERM` closes the server: every stream gets `end: stopping`, each store closes, and each lock is released. A second signal exits at once with status 1. | A close waits for running tools to settle, which a hung shell command could delay without end. |
| `tau device …` output | The design names the commands only. | `pair` prints the code and when it expires. `list` prints each device with when it was paired and revoked. `revoke` prints `Revoked.`. An error goes to standard error with status 1, and a wrong command prints the usage with status 2. No command prints a token or a hash. | The owner reads it on the server's machine or over SSH. |
| The `tau` package | The sketch imported `tau-websearch`, `tau-w2`, and `tau-w1`. | `modules = {}` and only `tau-host` among the Tau packages. | The kickoff starts the map empty. A later unit adds each extension. |
| `nix build` | A derivation that reuses the check commands, or its own. | `packages.<system>.tau`, the default package, builds the workspace with `tsc -b`, copies it to `lib/tau` with its links, and wraps `node` as `bin/tau`. `nix run .#tau` runs it. | The commands link into the checkout. An installed command needs links inside its own output. |

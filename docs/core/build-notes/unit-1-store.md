| The type of `then` in `RequestDraft` | Candidate 2's pi-durable `Task<DecisionInput<C>>`, or candidate 1's structural projection. | Both. `ThenTask<C, I, S, R, H>` is a full pi-durable `Task<I, S, R, H>`, with its own type parameters inferred apart from `C`, and also a `definition` whose `initial` property takes `DecisionInput<C>`. `RequestDraft<C, T>` takes the task's type as `T`. `request` infers all of them, with no type argument and no cast. | Measured with `tsc`: pi's `Task` is invariant in its input, through `migrate`, so `Task<DecisionInput<C>>` refused a task that accepts more choices than the request offers. The projection alone was too loose: it accepted an object with only a `name` and an `initial`, and `answer` then ran the registered task of that name with a choice it does not take. Now a property `initial` is checked contravariantly, so a task that takes every offered choice fits and one that lacks a choice does not, and the `Task` part refuses anything that is not a whole task. `test/types.test.ts` holds each case. The store's test helper names its draft type as `RequestDraft<Choice, typeof Then>`. W1, W2, and the host tests compile unchanged. What the type still cannot prove: a complete task object made by hand with the name of a registered task type-checks. TypeScript cannot tell where an object came from, and `answer` finds the task by name. |

## Verification

The emitted package was loaded by name, `node -e 'import("tau-store")'`. The root exports `decision`, `emit`, `eventLog`, `request`, and `withdraw`. `tau-store/host` exports `answer`, `openStore`, and `watchOpen`.

Four mutations of `src/decisions.ts`, one at a time, each failed a test and were reverted: reading the family without the counter check, creating the `then` task again after any terminal outcome, creating it without `background`, and leaving the answered record unwritten in the answer commit. The last one failed K6 on SQLite with SIGKILL.

Three more mutations of `request`, one at a time, each failed "a draft that differs from the open decision in one field supersedes it and opens a new ID" and were reverted: dropping the comparison of `choices`, of `conversation`, or of `then`.

Not tested: a kill in the middle of SQLite's own write, power loss, a Linux run, and a client placing an annotation.

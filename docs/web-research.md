# Scoped web research

Engine consumes the published `webfox` 4.8.0 root export, not `webfox/durable`. Pi Durable / Pi AI / Chord remain exactly 1.4.0. `package-lock.json` locks the dependency closure; upgrade Webfox/SDKs only with review and rerun the fixture, cancellation, interruption and control checks. Current SDK closure: exa-js 2.27.0 and @tavily/core 0.7.14. No live service/key was used by repository checks.

## Trusted configuration

The composition root constructing `Engine` supplies `web: { exaKey, tavilyKey, exaBaseUrl?, tavilyBaseUrl?, attemptMs?, overallMs?, cacheTtlMs? }`. The default Engine has no web credentials. URL overrides are trusted integration/fixture configuration, never model arguments. `createWebfox` receives an explicit config, empty environment and literal cwd `/`; no config-file, home-file, command credential, cookie, browser, video or provider selection is exposed. The CLI currently has no settings import or credential provisioning facility; a trusted embedding supplies these values. Native model provisioning remains a separate prerequisite from web provisioning.

Engineering defaults (not human-selected spending policies): 4 inputs of at most 2,048 characters; 5 discovery hits/query; 30 s overall deadline, 10 s attempt deadline; 5 minute working-result TTL. Trusted durations must be integral 1–600,000 ms. No transport retries, parallel providers, quality top-up or third provider. Inputs are normalized and indexed in original order. Exa success, including empty/usable partial material, is final. Webfox's structured unavailable/retryable service failures (including HTTP 429 rate limits) and locally missing Exa credentials admit Tavily. So does a settled `PROVIDER_FAILURE` with `retryable: false`: Webfox 4.8.0 discards the HTTP status and tag, so documented HTTP 402 allowance/budget exhaustion looks exactly like an HTTP 400 invalid request, a 401 rejected key, a 403, or an SDK error with no status. By explicit human decision, indistinguishable from exhausted counts as exhausted. This can start an unnecessary, potentially charged Tavily request, which the human accepted. The Exa observation keeps its failure and states that fallback eligibility was uncertain, without claiming a status or reason; it asks for Exa provisioning to be checked. Render does not classify from message text. Failures Render can identify still do not admit Tavily: page results (no `retryable` field), input rejected locally or by the tool schema, and other Webfox codes such as unsupported semantics. A thrown failure with no code stays `UNKNOWN_FAILURE`. More robust classification is tracked separately in https://github.com/vicrdguez/render/issues/41. Both failures/not-attempted reasons survive admitted fallback.

Webfox 4.8.0 races SDK promises against deadlines. Its Exa/Tavily adapters do not expose the underlying SDK's local settlement or pass their request context into these calls. Consequently Render **does not admit timeout fallback**: the observation is uncertain, possibly charged, with local settlement unconfirmed. In-flight cancellation carries the same uncertainty and an explicit `canceled` fallback reason, for either provider. Cancellation/deadline/current-authority checks prevent new admissions, not upstream termination/refund. An explicit later tool invocation is a new potentially charged observation, never replacement bytes. Unsafe tool replay plus startup uncertainty refusal prevents automatic primary/fallback replay after process death. Reconcile the original execution before supported explicit recovery; do not patch replay policy or edit SQLite to force resume.

## Tools and retention

- `web_search({queries})` and `web_contents({urls})`: unsafe replay. Only HTTP(S) contents URLs without embedded credentials are accepted. Return bounded substantive `output`, actual provider, request/observation IDs, input index, query/URL, version, times, digest/completeness, failures and omissions. Each observation has a fresh identity independent of its digest. Provider metadata outside normalized text is omitted; this is not an archive of all provider response fields.
- `read_web_result({handle,offset?,limit?})`: safe, no network; UTF-16 character paging of the serialized full bounded working envelope, maximum 16,384 characters/page. Offsets select data, not host files. Ordinary `read_artifact` refuses working handles to prevent an unbounded tool-output bypass.
- `retain_web_evidence({handle,observation,start,end,claim,stance})`: safe Ledger command/receipt. Copies exact selected text/context (at most 65,536 UTF-16 characters) from current authorized working bytes; the model cannot submit substitute provenance or bytes. Stance is supporting, negative or conflicting. Stores an immutable ordinary document revision with selected/full digests, source/final URL, request/provider/version/observation/times, completeness/omissions, failures, claim and assignment. Retain enough surrounding text to inspect the claim; retain whole pages only when necessary.
- `submit_role_result({text,supports})`: the list is mandatory. `supports: []` explicitly declares **no web reliance**; otherwise list every exact promoted evidence revision the report relies on, including negative/conflicting material. Omission is refused by the registered tool, Ledger parser and Kernel. Required web support must name already promoted, intact, own evidence revisions. A working handle, URL or digest is not retained support. The command links these exact support refs into the report fact and commits `webEvidence: none|retained` in the acceptance receipt. Historical reports without that field remain undeclared, never retrospectively classified. Kernel checks the explicit declaration and references; Ledger verifies their bytes/schema in the accepting transaction. This machinery does not detect undeclared natural-language reliance or prove the agent selected sufficient/contradictory context; those remain review/judgment obligations. Unavailable checkpoint/decision APIs still refuse, not waive their future evidence requirements.

The three layers are deliberately different:

1. Ledger-authorized, assignment/generation/Attempt-private in-memory working envelopes: 262,144 characters of normalized text per observation; at most 16 envelopes, each at most 4 MiB serialized, in a host. Eviction/expiry/restart may remove them. Scope is checked before disclosure, including known foreign handles; IDs alone grant nothing. Temporary artifact responses are explicitly labeled `temporary`. They are not acknowledged immutable revisions and never enter history/export retention. Reads after loss return `working_result_unavailable` without contacting providers.
2. Ordinary committed bounded Durable tool outputs remain in native conversation entries. Preview text is limited to 2,048 characters/observation and labels omissions. Native history retention is unchanged. The existing client export still explicitly declares runtime-transcript capability unavailable; a full new transcript export is not claimed here.
3. Selected Ledger evidence uses existing exact revision reads/history/export/integrity and startup paths, independently of the working cache. Cache cleanup never touches immutable revision entries. Missing/corrupt retained support requires those exact bytes; refetch cannot repair old refs. Ordinary exact reads/history/export and restart remain supported. Disaster recovery is deferred after v1; required runtime evidence is not constrained by package representability.

Web text stays inert. Configured keys are redacted from retained normalized content, URLs and query provenance; provider errors expose classified codes, not credential-bearing SDK messages. This does not classify arbitrary third-party private information in public web content.

## Verification and limits

`npm run verify:scoped-web-research` uses owned HTTP responses with actual pinned root Webfox: classification rows at the `research` interface, journeys through Engine registered tools, Durable transcripts and real SQLite. It covers empty success, rate-limit fallback, documented allowance and erased invalid-request fallback with uncertain eligibility, identifiable page and local-input exclusions, missing fallback key, tail content, distinct equal-byte observations, known foreign scope, unsettled timeout, cancellation, primary/fallback process interruption after an HTTP 402 primary, negative evidence retention/report/reopen/export and model-selected host/config/provider refusal. `RENDER_V3_REPETITIONS=100 npm run verify:scoped-web-research` repeats each named crash boundary 100 times. `npm run verify:unsafe-controls` includes fourteen web mutations with independent assertion messages; setup failures do not count as detection. `test/web-error-boundary.test.ts` retains the actual-root diagnosis: controlled HTTP 400 INVALID_REQUEST_BODY and 402 NO_MORE_CREDITS with equal message text produce identical complete public errors, while page failures and local URL validation stay distinguishable. This is controlled-response evidence of information loss, not a claim about live error messages or how often a fallback is unnecessary. See `docs/verification/scoped-web-research-decision.md` for this rule's failure cases and `evidence/scoped-web-research/decision/` for its results; the earlier rework and ambiguity diagnoses and evidence remain retained as history.

Fixture checks establish no live Exa/Tavily auth, quality, spending, Linux behavior, human handover judgment or full future V8/V9 product journey/load. The negative-evidence journey is the currently available composition, not checkpoint/annotation/experiment features from later slices. The initial failure-case document and first executable scenarios preceded product changes; additional cancellation/process/control and composition evidence was added during implementation. That is narrower than the Contract's requirement that **all** executable scenarios and targeted controls precede product changes; no retroactive preimplementation claim is made. The recorded human decision permits continuing without rewriting that history. Continuation failure cases, executable scenarios and targeted controls precede its product edits (`docs/verification/scoped-web-research-continuation.md`); they add mandatory declarations, damaged-support restoration, mixed/partial/both-failure batches, remaining/expired deadline fake-clock cases, timeout with/without remaining time and actual secret echoes. The initial deadline mutation also had to remove the timeout clamp to reliably exercise the intended forbidden network request; its earlier failedOtherwise result is retained, not counted as detection.

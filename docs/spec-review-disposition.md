## Human decisions

### D001 — Delegation maximum (A003)

Human answer to the numbered choices: **“1. B”**.

The explicitly labelled B in the presented table was: configurable delegation of **technical Seams and Modules decisions within the agreed scope**, with **final Contract acceptance remaining human-owned**. Every option retained independent review/evidence, human handling of new product choices outside delegation, and human-only final main merge.

A later research update corrected the historical account: original skl allowed Modules and Proposal delegation, but not Seams. It offered an unlettered revised recommendation, not a replacement B. Parent explicitly acknowledged the human's labelled selection as B from the options table. Therefore apply the labelled choice, not the designer's original recommendation: Seams technical decisions are delegable; Proposal/Contract acceptance is not. This is an intentional redesign of the original scope.

Initial human-routed settings remain the conservative proposed default; no live delegation is granted. Config changes, scope/version/provenance, exact emissions, independent review, product-question escalation and Contract freeze still require explicit semantics.

### D002 — Worker network baseline (A006)

Human answer: **“2. A”**.

Normal public-internet access for dependencies and research. Host/private/tailnet services require an explicit project/profile grant. Verification services within the worker environment remain available. Restricted mounts and absence of host credentials remain; allowed public egress is NOT a source-exfiltration-prevention guarantee.

This selects the policy, not a particular proxy/firewall/platform implementation or proof of enforcement. Choose a proportionate existing mechanism where possible; verify the actual execution/tool paths. No network configuration was changed.

### D003 — Backups and proportionality (A020/A022)

Human answer: **“3. A is ok, don't overthink it. we just need some backups and an acknowledged RPO/RTO. As mentioned in the notes, recovery-loss is important but scaled to personal, self-hosted operations not an enterprise solution”**.

Selected option A: asynchronous off-host protection, targeting at most **five minutes of exposed acknowledged work while backups are healthy**, prompt backup after important design decisions, actual protected cutoff visible, and continued local operation with a warning during backup outages. This is not a hard loss guarantee during outages.

The parent acknowledged manual, best-effort recovery without enterprise availability machinery or an invented time guarantee. No numeric RTO, destination or tool was selected. Keep these proportionate: document restoration steps, measured bounded probe time and operator prerequisites; do not introduce synchronous remote acknowledgement, failover, replication or an all-failures claim. An operator-provisioned backup destination can remain a deployment prerequisite rather than a new architectural research program.

### D004 — Configuration changes and active work (A003/A007)

Human answer: **“4. A”**.

New configuration applies to future work by default. An explicit action applies a selected revision to selected active work. Revoking authority takes effect immediately. Existing review counts and historical decisions never reset. This chooses application semantics, not a live configuration change. Preserve exact policy/delegation provenance and current authorization checks.

### D005 — Proposal PR timing (A009)

Human answer: **“5. A”**.

Create one draft proposal PR after the first qualifying local integration, then update its source and lower-resolution summary as work progresses. Publication failure/uncertainty does not block eligible local work. No Slice issues are published. Exact current published-source mapping remains necessary before declaring final merge readiness; only the human merges main.

### D006 — Immutable document storage (A019/A020)

Human answer: **“6 A”**.

Select **A: immutable acknowledged text/document revisions in SQLite**, alongside transactional history/authority, receipts and task handoff. Canonical source code remains in Git. This supersedes draft statements that the document backend is unselected; SQLite plus external document CAS and SQLite plus Git-backed documents are evaluated alternatives, not selected implementations.

The presented A recommendation retains all acknowledged document history initially and provides a versioned nonauthoritative text/JSONL export for inspection and future evals. Complete recovery packages include the database and required source/artifact objects. A Git-readable archival projection remains optional later convenience, not a required second store or authority. Immutable revision identity remains distinct from content digest; current pointers never erase rejected, abandoned or superseded revisions. Unsaved buffers, uncommitted provider tokens and unsnapshotted worker files are outside the acknowledged-history promise.

This selects the design representation, not prototype code, production schema or deployment. Full-text growth is an acknowledged trade-off. Actual large/binary execution artifacts may require separate owned storage; ordinary text-heavy documents do not require it merely because they are text. D003's asynchronous off-host policy is unchanged. The bounded history probe establishes local process-crash/history/export/clean-directory-restore behavior, not production authentication, complete restore reconciliation, off-host operation or physical durability.

# Off-host protection: preimplementation failure cases and literal oracles

Owned seams: Ledger command/observe/artifact through HTTP/admin sockets, real SQLite packages and the production receiving process. The SSH executable is a controlled external transport fixture: it runs that receiver against an owned directory on this machine. This proves publication/integrity/restore behavior, not a deployed remote host or physical durability. No live services or provisioning.

- O1 / B1: configuration, scheduled work and a local package do not establish protection. Before a durable verified remote reply, protected generation/cutoff/time remain null. A copied package with a missing or malformed durable receipt cannot advance them.
- O2 / B1,B3: first generation covers enrollment/workflow/save at sequence 4. Subsequent saves reach 5 and 6 while destination fails/corrupts input. Cutoff remains 4, exact revision:6 remains readable, warning visible, and old destination generation remains valid. Recovery advances only after newly checked publication. Restart retains the last verified identity and pending exposure.
- O3 / B2: prompt save trigger does not wait for periodic cadence; periodic enrollment/message work is backed up within 60 seconds plus actual snapshot/transfer duration. Measure the whole first-acknowledgement-to-publication window, not just timer delay. Delayed transfer over 300 seconds reports overrun even after success; idle time alone reports zero exposed work. Fake clock represents scheduling variability only; real bytes and actual receiver still run.
- O4 / B1,B3: kill receiver before publication or after publication before receipt; host cannot advance protection from an ambiguous transfer. Local saves remain accepted, prior generation survives. In-flight corruption refuses and cannot replace the old package.
- O5 / B4: delete original store and local packages; restore solely from owned destination generation at cutoff 4. Original credential is fenced. Repair/re-enroll recovers literal `protected\n` at revision:4; missing post-cutoff command remains `outcome_unknown_after_restore`, writes remain `recovery_required`. Report measured bounded elapsed time and missing real deployment/tool/effect-reconciliation prerequisites, not an RTO.
- O6 / A4,T3: snapshots, history/export operational backup declarations and package-contained retained status survive normal restart and clean restore. Status is current operational information, not a fabricated fixed-cutoff history record. Unknown/malformed backup state refuses package validation; no secret SSH configuration in package/history.
- O7 / B3,A2: absent configuration warns without halting local work. Nonempty role-work packages retain the inherited explicit reconciliation refusal; no incomplete package is called protected. Scoped/unauthenticated clients do not gain destination paths or extra content.

Unsafe controls: skip remote receipt validation (copy-only treated as protected), and advance protected state before transfer. Each must fail an explicit assertion about unchanged protected cutoff, not import/setup. Existing package, recovery, authority and history controls remain cumulative.

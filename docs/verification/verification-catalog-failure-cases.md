# Verification catalog preimplementation cases

Written before product changes. Existing boundaries: Engine renders retained packets and owns owned-check orchestration; Effects resolves literal source; Sandboxes executes Linux commands and journals decisive results; Ledger retains exact documents and checks trusted provenance; Kernel admits reports. No new scheduler or module boundary.

## Literal observations

- C01 (B1/A1): explicitly select `.skl/verify.md` in a trusted source containing an unusable `.render/verify.md`. Packet includes exact selected bytes/digest/commit, Contract revision, Doctor prerequisites, ordered `endpoint, static` ranks and the exact selected rows. Commands come only from those rows, not the legacy operator argv. Unknown/missing/duplicate rows, malformed ranks, changed digest and symlink assets refuse rather than fall back.
- C02 (B2): discovery prints `INDEX ONLY` and exits zero; journey steps print `STEP OK` and its independent sanity exits 9. Discovery has no proof rank. A human row is advisory/unrun. Receipt retains both journey results and cannot qualify for behavioral completion. Channels do not alter rank.
- C03 (B2/B3): required full-suite, typecheck, lint and cited behavior run on the same exact source. Green command receipts yield `needs_assessment`, never semantic pass. A model must explicitly declare assessment and justification. Claimed rank cannot be stronger than the weakest required evidence; a project minimum stronger than that evidence blocks pass. Generated/human rows cannot discharge required behavior.
- C04 (B3/A3): assessment must use trusted runner receipts with exact repository/commit/asset digest/Contract/row selection and the same role, not another role's execution. Old source, old verifier, missing required checks, failed sanity, interrupted checks and mutated result source block a pass. A non-pass report remains possible. Implementer receipts cannot satisfy Watchdog. Required input bytes are integrity checked again at submission, not merely at assignment.
- C05 (B4): retain command and sanity output before running catalog cleanup. Failed cleanup leaves explicit pending status and exact retained source/diagnostics. The runtime is quiesced by the inherited stop/seal path; the source root and journals are not deleted by product cleanup. Native prerequisites missing on Linux remain unrun/blocked, never executed in host shell.
- C06 (A3): catalog execution and assessment documents survive scoped history/export/reopen with exact bytes and provenance. Role/source packages continue to refuse unsupported recovery instead of dropping records. Existing root-crash/cancellation checks cover the inherited trusted source and journal barriers; no new barrier is introduced.

## Verification selections and limits

Fast checks use real Ledger/Engine and Git without Docker for packet selection, structural completion refusals and policy ranks. Linux execution/journey/cleanup uses the existing owned container fixtures and is integration-only. Literal expectations above are independent of parser/evaluator implementations. Targeted unsafe controls remove discovery/rank and identity guards and must fail their corresponding assertions, not imports/setup. Full Gate remains `npm run verify:gate`; extended and unsafe-control jobs remain separate. Full V8/V9 and role/source package restore are absent, not fabricated passes. No live model, external service, human trial or native Mac execution is authorized by these fixtures.

# Failure catalogue

> **Supporting file of the Render UI spec** ([`spec.md`](spec.md)). It is copied from the design workbench (`~/dev/render-ui-design/design/`) as of the final phase.
> - **File names** in code spans: `visual-language.md`, `grammar.md` and `stack.md` are in [`reference/`](reference/); `layout.md` and `text-mocks.md` are in [`wireframes/`](wireframes/).
> - **Measured, proposed and pending** claims are separated in [`evidence.md`](evidence.md).


Written before any mockup or keymap entry, per `CLAUDE.md` ("FIRST write all the ways it could fail"). Every screen in `text-mocks.md` and every rule in `grammar.md` cites the IDs it defends. A failure without a check is a design gap, not a defended case.

**Scope.** Ways the client can (M) mislead about state, (T) act on a different target than the one shown, (S) let agent content impersonate chrome, (K) trap the keyboard or muscle memory, (L) lose input, (W) mishandle the wire, (R) fail re-entry, (P) degrade under load into one of the above, or (Q) be unpleasant or misleading to read. The Q group exists because an early prototype shipped mid-word wrapping that no check caught. Server-side guarantees (spec I1–I20) are assumed; this catalogue is about the client making them visible or wasting them.

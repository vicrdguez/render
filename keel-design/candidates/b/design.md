# Keel: approve the contract, not the conveyor belt

## Problem

One developer should be able to leave three workers running and still know exactly which promise and which code a green check covered. A decision about one seam must neither authorize work against its obsolete signature nor put a different worker on hold. Tau gives us an atomic store line, immutable entries, decisions and restartable tasks, but neither a transaction with Git nor an intercept on a client's `input` call. Those constraints matter more to this design than the sequence of stage names.

## Usage (caller's view)

**Owner.** Create a Keel conversation and say “Fix the duplicate fee; here is the failing trade and the expected net.” Open the event to follow the worker if interested; otherwise the next thing to read is “Landed on trunk at …”. For a new pricing interface, discuss direction with the designer; open a node's basis, read both complete candidates, pick a base, select text and answer *revise*. The next basis opens with numbered replies. Each rider gets a separate, plain choice; accepting a node is not accepting its incidental choices. Mark text on a candidate, report, tool result or handover as a finding without disapproving everything else. Review the investigator's recommendation, then build, defer or drop it. The client uses ordinary Tau `create`, `input`, `open`/`history`, `inbox`, `answer`, and `timeline`. For a selection outside a decision, Mark uses a nonblocking project “File a finding” decision; no model has to relay the comment. Promotion is the owner's Git operation from the named commit, never a Keel button that merges to main.

**Agents.** The designer gets the owner's actual prompt, repository reading tools, and `ground`; an approved reference bypasses Shape. In Shape, `dispatch` sends a question to the allowed seats, then returns their separate reports, including failures. The designer publishes a synthesis, not a claim of approval. The coordinator reads the current plan and changes pending goals/dependencies, not code. A worker reads its brief, writes within its fences, records a ruling and publishes a report without supplying a hash. A verifier reads a sealed revision, runs the project's proof and returns a verdict citing actual runs. An investigator files evidence and proposes batches. Explorers, source investigators, candidates, judge, diagnostician and challenger get their own instructions, models and capabilities; no child can dispatch. No role gets an `advance_stage`, `approve`, `git_push` or `set_state` tool.

```
worker: ruling({decision:"Round once on booking", why:"The approved booking rule fixes the rounding point", cites:[feeRule], costIfWrong:"Balances drift per trade", severity:"money"})
worker: publish_item({report:"Removed the second rounding", addresses:[priorBlock]})
verifier: run_check({check:"net-fee-repro"})  → run receipt; verdict({result:{kind:"pass"}, checks:[receipt], prior:[resolvedBlock], notes:[], tripwires:[]})
```

**Tau host.** List the installed `keel` workflow; read its flat, closed options schema. Create the entry conversation with the project's cwd. Register the same named, versioned tasks before resuming the project's store on restart. No project discovery task at import time, plugin RPC, or new core primitive.

**Another extension.** Supply a named roster that resolves a seat to closed child settings and an input derived from *that extension's* facts; install the returned tool on the parent only. `dispatch({jobs:[{seat:"reader",question:"Who calls append?"}, …]})` returns one durable, addressable answer or non-answer per job in input order. No Mandate, branch, project queue, or Keel model option comes along.

**Next engineer.** To change when a repeat review is a block, open `verify.ts`, its situation template, and the Verify contract tests. To change a rider choice, open `design.ts` and the corresponding basis template. To change what happens *between* those lanes, open `crossings.ts`; that is a different decision. Storage tokens and effect runners are not importable escape hatches. For example, `Verify.receive(work, {kind:"item", item, submission}, turn)` has all the authority required to open a review, not the authority to patch the worker's plan.

## Shape

**Three decisions carry the design.** (1) Separate a *binding edition* from an *assignment*: a worker acts on specific nodes of one edition, not “whatever stage the project is in.” (2) Cross lanes on the store's commit line; do not build a workflow interpreter, broker, or outbox scanner. The durable thing that still has to happen is a Tau task created on that line. (3) Verify an installable Git object, not a directory and not a proposed merge. The receipt for installing it lives on both sides of the store/Git gap.

### Data before control

| Durable object | Owner and address | Dominant read |
|---|---|---|
| Work identity | The root designer's ownerless conversation ID, unique within the project; also the address for its Mandate and plan docs. Not a project-global “current work”. | An event, brief or finding links directly to the work. |
| Mandate | Design's conversation doc holds the binding edition pointer, current explicit design situation, rounds and live proposals. Each edition, draft, complete candidate, experiment frame/result, challenge, judge, round and review basis is an immutable version-tagged entry. | Load the edition by ID, then the named node or source; read previous rounds without replaying chat. Round snapshots distinguish “offered” from “settled”: a settled snapshot links back to its draft and actual answers. |
| Plan | Build's conversation doc on the root points to the coordinator and stores an ordered pending list, active items, holds, verified item receipts, plan serial and closure. Each worker has its own conversation doc of rulings, submissions and process notes. | Given a key, find its dependencies or verified receipt in this plan; given a worker report, read its original brief. No scan across all workers to schedule an item. |
| Verification | Verify owns review history and finding threads, keyed by persistent subject (item or build) on the work, not by the newest verifier conversation. One fresh reader assignment addresses an immutable target/review attempt. | Load the last verdict, prior blocks and reviewed fixes for this subject, including during full/combined proof. |
| Queue | One session doc, one project desk address. Rows keyed by finding page, report, batch and disposition; override obligations and sweep cursor here. New investigators can work on different rows while triage is open. | Scan open rows plus the named plan for duplicates; show a batch by ID. Keep deferred/dropped/duplicate rows addressable. The owner reads visible bases/events, not this doc. |
| Control | A small per-address turn book: current assignment, due/open subjects, consumed causes, work membership and cancellation. A session directory registers roots and queue address, without copying work status. Each role records its address; children belong to their dispatch task. Project desk has its own book. | One lookup for replay, one for expected decision, one for which conversations to drain. No dependence on extension docs showing in the client. |
| Repository | Session doc has the bound repo, one FIFO landing slot, one integration slot per build and the leases. An operation has an immutable intent and a versioned executor checkpoint; permanent result page belongs to the work, not to a retiring task doc. | Inspect a specific op/slot and named refs. No scan of every project worktree on boot. |

Full content is on the page, not in an absolute temp path or just a model summary. A page is an actual entry with `data.text` for the client, schema/version and typed payload for code; headline events point to pages and conversations. Ranged bases use that exact text, UTF-16 offsets. All IDs are store-local. Domain records use labelled IDs; untrusted strings/entry IDs are decoded, checked for kind, work, subject and provenance at ingress. The brand alone proves nothing. The only shared mutable rows on hot paths are genuine agreements (a plan, a decision slot, integration into the same ref); an item worker never rewrites a shared plan. This is *separate before serializing shared state*, applied even though Tau serializes commits anyway.

### One turn and the work it leaves behind

One adapter for tools, one for the host's answer task. On the serialized store line: return a saved receipt first; do **all table reads** (entry kinds, actual actor/run, decision, witnesses); then hand a `Turn` to the lane. It may read/write docs, append pages, cross lanes, emit and create tasks. One immediate commit includes publication, receipt and scheduled consequences. No Git, harness getters or agent waits inside it. Model-only sequential replay-safe tools use `api.taskId`; duplicate *new* calls must also satisfy the assignment/version precondition. The answer adapter uses the **decision ID**, not the replacement then-task's ID. It reads annotations with `decision(tx,id)`, verifies expected purpose/basis/ticket and applies once.

An assignment is permission to act on particular terms, not permission attached forever to a conversation. Match the actual admitted input/run using its saved submission and `LiveDoc`. Revoke at pause, cancel, rebrief or affected term change; don't reuse that actor until the old run drains. Check again before **authorizing** a Git install. Unrelated assignments don't depend on every edit's plan serial.

Every wait that matters has a named, versioned `defineTask`. Commit changed checkpoint, wait/sleep or terminal outcome, even for obsolete work. Create/configure a role and schedule the first delivery together. In a **later** commit, with its handle acquired outside the callback, configure and submit **before** any table writes; use the saved rendered bytes, `keel.input` entry kind and cause-derived request ID. On restart reattach to the same submission. An unanswered run or a fluent answer without the required publication isn't completion. Record an interruption and offer retry/close; use host `faults` for a faulted executor. A retry gets a new authorized identity, not new bytes behind an old request ID.

**Raw direct input is the exception that matters.** A client can message any role; hooks can't veto admission, and a queued input isn't a transcript entry yet. Don't open a decision mid-generation. Stage the typed offer and input witnesses; an arming job waits for the authority conversations (designer, or investigator and paused target) to drain, then checks idle, successful delivery and last placed *owner* inputs against the original stamps **inside the opening commit**. A failed run with potentially retained input is not a drained success. While open, invalidate the question before any Keel input to those actors. A first direct input after arming therefore places a distinguishable `pi.user`, or follows another direct input that already did. Don't watch unrelated workers. The offer task watches `LiveDoc` and its expectation doc (subscribe, then reread; reconstruct watches on restart), withdraws on change, and exits on consumption. Crucially the **then-task repeats the check**: if the host answered before withdrawal, emit “obsolete”, do not advance, and present a fresh basis after redirect. Domain changes withdraw affected slots in their changing commit. No promise that stock Tau literally rejects every racing answer.

Cancellation is a workflow choice/instruction: mark cancelled, revoke tickets, withdraw outstanding decisions and schedule the drain **before** any ordinary role abort. Stop this work's members, cascading to dispatch children; repeat safe stops after reopen. Reconciliation of a ref install already durably authorized must finish and report the actual result, not say “undone”. Native `stop` is Esc, not a workflow cancellation.

### Authority at the three lanes

**Design.** Ground presents evidence, gaps and contradictions with `how`/`why`; apply the same approved-reference rule to a queued prompt. “Bug” alone can't bypass a new seam. An undetermined direction/stack, seam, contract, rule, first-of-kind or proof strategy gets a node round, top down. Shape records the common frame, different-family candidates, cross-family judge, synthesis/grafts with provenance, then a challenger. For observable disputes, freeze one axis and decision rule **before** prototyping. Judge and synthesis each identify unasked choices. Failed attempts stay visible but don't count as two complete candidates.

The basis contains usage before types, callers now/later, rationale/sketch, rule→falsifier→ranked proof, protected checks, anti-criteria, precedence, all candidates and labelled riders. A base choice orders synthesis, not approval. Owner can also revise, approve, order seeded/fresh arena or decline. After node choice decide each rider separately: keep/drop/defer/design. Defer files a finding; design returns it to the frontier. Bind only retained terms. Each annotation has (decision, ordinal, range/text) and a numbered reply on the next or final response. Reject missing/duplicate replies; on decline record not-adopted dispositions. Re-show material changes; carry approvals on identical content only.

**Build.** The long-lived coordinator proposes a serial-checked replacement of the pending goals/dependencies, never edits code. Check acyclicity, existing dependencies and immutability of active/verified records. A correction to finished work is a new item. Encode verifies scaffold, boundary rules, protected tests and project proof strategy before fan-out. A one-item repair may narrow one worker's proof-writing assignment to body-only after sealing its test. Extend the verification playbook for new rules under explicit Encode authority; record tests-after-code breaches and continue, don't redo history.

On claim, pin the actual build tip and open the worker tree. Only now resolve goal/evidence/fences/checks from current code and terms, requesting coordinator judgment if needed. Recheck before issuing the brief. A worker records its ruling, citations and cost if wrong; unapproved patterns remain unapproved and go on the options list. For a pivot, hold named terms/items; on approval store the new edition awaiting a pending-only plan edit. Installing that edit and `plan-bound`/Design activation share **one commit**. Unrelated work can proceed in the meantime. Rebrief only those affected and release only the resolved hold.

**Verify.** A different author/model runs the project's verification on the sealed target. Receipts bind actual actor, revision, recipe, exit and output. Compare protected diff, rules/probes and all project principles with rulings/delivery evidence. The exact block reasons are `BlockReason` in `verify.ts`; supported edge-case harm must meet the path's zone. Anything else is a note plus filing, with failure/likelihood/complexity for speculative handling. A broken rule is rework; a proposed description/binding change is a separate finding.

Each repeat verdict accounts for each existing block by stable identity, observation and evidence. Semantic matching is verifier judgment, not fuzzy string matching; require the prior IDs so it can't silently start a clean ledger. Count only distinct **addressed fixes** independently observed to survive. On two, freeze that target, dispatch a fresh diagnostician, then bring the diagnosis to triage. No round cap; merge conflicts aren't findings. Weakened protected checks and repeated workaround/escape-hatch scrap tells are tripwires. Ordinary failures return to Build without the queue. A full-set failure opens a repair item; additions/holds invalidate a closure even when its hash didn't change.

### Install the thing that passed

Only `repository` mints meaningful revisions. First commit the external recipe: repo identity, owned paths/refs, expected source/target, operation nonce and deterministic commit metadata. For checkouts require an exclusive path, marker and matching Git registration/ref/head; ambiguous partial creation, dirty foreign artifacts or a target checked out elsewhere → preserve and surface, never force-remove. No model-supplied shell, refs or hashes, no push, no main.

Seal closes writes and validates the entire diff, including new files and protected baseline. Capture the manifest then use a private index to construct immutable objects. Changed bytes aren't the old report. Store expected old and prepared new commit before updating the named ref. One `git update-ref --stdin` transaction does old→new **and creates K→new** for this operation. Store acknowledgement follows inspection: matching witness = already happened (even if the target subsequently advanced); no witness + expected old = safe to attempt; other evidence = stop/replan. No timeout steals a reservation.

Verify first on the worker head. Under that build's integration slot combine it with the *current* build tip; verify the combined candidate, or reuse proof only for the identical commit and obligations. Install and append immutable item-record before releasing dependents. Integration conflict is a fenced Build repair against a new base, not a verdict round. After all items, the full-set pass admits the build to the **project** landing slot. Take trunk into the build branch; create a single-parent commit on current trunk from that combined tree. Verify **that exact prospective trunk commit** before CAS. On conflict/failure release reservation for rework; on return re-read trunk/closure and renew applicable proof. No item install may invalidate an authorized landing. Clean reviewer checkouts are removed after each pass; run scratch is separate, failed evidence persists.

Release the slot before handover. Owner gets intent/outcome, actual trunk commit, cost-ordered rulings and residual risk. Rejection files a missing-check finding; fix forward or separately verify a revert on trunk. Never move main.

### Queue, principles and dispatch

One finding page includes text, source selection, revision and report whether it came from owner, worker, reviewer or sweep. Reserve **one nonblocking project decision** as a finding inlet, opened on first work. The client’s Mark gesture answers it with “file” and a range-less annotation carrying the selected entry link, quoted text/range and comment. A plain client can paste that link/comment. Never send offsets into another entry as a native range of this decision’s basis. The continuation verifies the authenticated decision and target projection, files all valid marks or requests correction, then re-arms the slot. No LLM or afterRun hook on this path. Retry the **same** answer if its acknowledgement is lost; concurrent different answers conflict, so resubmit the unaccepted mark to the next slot. Inside an actual review, an explicitly marked annotation uses the real basis/range. Both feed the same Queue.file. Unlike a review, the inlet confers no authority over any changing terms: only its own expected decision matters. It occupies one inbox row on a generic client but stops nothing. “Dismiss” closes this sheet; the next project turn can offer a fresh one.

First reproduce/measure (or document non-reproduction), search queue and plan, classify and size. No arena. Duplicate links to original; defect against current Mandate automatically adds a coordinator discovery. Otherwise the investigator groups findings by one cause **and** one owner decision; reject overlapping or incompatible members. Build a determined follow-up directly, start Design for precedent, revise the **same** work for wrong terms. Filing holds nothing; an investigated proposal holds specific items/dependent starts. Defer/drop retains history and doesn't bless known-wrong semantics. Money/external effects are owner stops: a “build” answer is not execution authority.

Each owner override owes a check or principle; record original evidence and keep the obligation owed until evidence of encoding, even if deferred. Revocation migrates callers and fails the old shape structurally. A project background task reschedules a sweep with durable `sleepUntil` for architecture/proof/ADR drift and citation patterns; file via the same intake. Start it on the first real turn, not module import.

For principles, a literal section returns the full, sorted names/descriptions iff `principle` is actually offered. Read protected project files at request time in the *actor's checkout*, including after compaction. Pull any body. Record its version and delivery (bound, triggered or pulled) separately from a ruling's citation, so missing delivery remains observable. Project files live under protected `.keel/principles/` and `.keel/playbooks/`; agents don't edit installed or protected prose. Fact bindings/event triggers are explicit, not evaluations of Markdown descriptions. Each lane case and role maps to a checked `prose()` template under the five `src/prose/` directories; store rendered bytes on admission. No “if you're retrying …” prompts.

One reusable foreground dispatch tool. The parent selects a permitted seat and question, not cwd, tools or model strings. In one commit create task-owned children and ordered manifest; separate cause-keyed submissions, wait all settled, keep answer IDs and non-answers in input order. Reopen the manifest after crash; abort cascades. A child is denied dispatch both by tool selection and caller check. Preserve full answers independent of bounded tool-result text. No dispatch for inter-lane transfers.

### Module map

`sketch/` shows the proposed interfaces and private stored shapes, not a second extension. In production these source modules sit directly under the shipped `src/`. Only `index.ts` is the load target. No generated JS or persistable closures. Imports below are permitted, not mandatory; TypeScript-only domain vocabulary is noted separately. In particular, lane A cannot open lane B's document token. Don't publish tokens or a generic “set document by kind” operation.

| `facts.ts` | Identities, evidence, approval, proof, subject and hold vocabulary crossing seams. No workflow switch. | Tau ID types only |
| `design.ts` | Ground/Shape tools and input cases, Mandate, approval frontier, rounds/riders, experiment/arena evidence | facts, turn, library; dispatch **results**, not child orchestration |
| `build.ts` | Coordinator and worker tools, pending DAG, briefs, assignments, protected Encode, rulings, closure | facts, turn, library, repository, workspace; Design edition contract as a type |
| `verify.ts` | Verifier tools and runs, finding identity/block bar, convergence, integration proof, Land and Hand over | facts, turn, library, repository, workspace; Build submission/closure/record types |
| `queue.ts` | Single finding inlet, investigation rows, batches, overrides, recurring sweep | facts, turn, library; Design proposal type |
| `crossings.ts` | Exhaustive delivery between the four owners and completion of an authenticated repository intent | four lane interfaces, facts, turn, repository |
| `intake.ts` | Decode owner inputs/marks, source identity, annotation projection; no authority for a model to answer | facts, queue finding type, Tau read surface |
| `turn.ts` | Replay receipt, ordered commit, assignment, owner slot/witness, admission, cancellation and drain | facts, Tau store/durable, seat types/role resolver; apply handler supplied at composition |

No run-time dependency cycle: policy descriptors/handlers are passed to adapters at assembly; type-only imports don't call the owning module. Private tokens and helper functions are lexically unexported in the owning file. Use compile-time exhaustiveness for lane exits/scene descriptors and a small import-policy test for illicit lane-to-lane writes or new raw Git/commit paths. Inside each lane the plan/settlement/convergence/eligibility rules are pure functions; its public receiver adapts store facts to those decisions. Don't turn the module table into a runtime plugin system. `tools/check-boundaries.mjs` currently forbids extension→other workspace-extension imports: a second extension can't legitimately import `keel/src/dispatch.ts` today. **Extract/move just that file** to a permitted shared dependency when the second real consumer exists. In the meantime its extraction test can register a differently named non-Keel parent using only its roster interface.

**Role menu.** All selected roles may read relevant evidence, mark a finding and pull any principle, subject to actual assignment. Designer: ground, frame, plan experiment, dispatch, submit round. Coordinator: read plan, revise pending, brief/claim ready, close plan; never repository writes. Encoder/worker: fenced edits, test/probe, ruling, publish item; no Git command tool. Integrator: only a conflict-resolution worker when judgment is needed. Verifier: inspect, run checks, verdict, dispatch diagnosis, compose handover; no write/merge. Investigator: assess, group, read queue/plan, dispatch cheap read-only inquiries; no arena at triage. Sweeper: inspect and file. Explorer/source investigator: read-only how/why reports. Candidates: isolated sketch text/files in immutable answers, never read one another. Judge: read completed candidates and rubric only. Prototype: scratch, one framed experiment. Challenger: read synthesis/evidence only. Diagnostician: read failed probe, actual fixes and results, never their author. An owner setting a conversation's model directly is not proof it differs: record the model that actually authored each submitted result, refuse a verdict that fails independence. Grandchild dispatch is denied at parent-authority check as well as omitted from both tool lists.

**Depth.** Build asks for one eligible item to start; it needn't know how the plan survived compaction or how a checkout recovers after `SIGKILL`. The verifier asks to pass a sealed target, not to lock trunk, invent commit trailers, or order shell commands. The owner sees “keep rider 2” and “landed at H”, not leases. The deliberate exposure is the *reason* crossing a seam (e.g. conflict vs. surviving block) and its exact evidence: hiding it behind a universal “next” would make each recipient reconstruct it. This follows *boundary discipline*, *make operations idempotent*, and *encode lessons in structure*. In the red-flag screen the tempting shallow module was an `IntegratorAgent` forwarding successful verdicts to Git; it has no judgment to exercise and isn't in the design. The sole shared committer earns its place by removing replay/order/cancellation rules from every publishing tool.

**Compatibility.** Start doc/task definitions at version 1 with stable names like `keel.plan`, `keel.review`, `keel.repo`, `keel.deliver`, `keel.git`, `keel.offer`, `keel.answer`, `keel.drain`, `keel.sweep`. Latest/initial-fork for working docs, immediate durability, finite delta checkpoint policy; don't fork an authority doc to give another actor rights. Task input and checkpoint migrate together. A change to *any* stored field bumps its owner's version and supplies a decoder/migration tested on an actual old snapshot; e.g. a scalar hold becomes a one-element cause list, **not** an empty list. No defaulting away unknown authority, unresolved finding or in-flight install. Immutable pages have a version envelope and old readers/upconverters; old decisions retain their offered meanings under the old purpose version (or withdraw before upgrade). Keep old task names/phases through drain; reject newer unknown data visibly. Options use Tau's fixed v1 helper, required base model and additive **optional** overrides with fallback: don't rely on that helper for arbitrary schema migration. Packaging check exercises `src/index.ts` and shipped prose without a checkout. Neither volatile module state nor a Markdown ledger is the record. After repeated crash cutoffs a task can fault at the harness restart limit; replacement work must recheck the original receipt/authority/intent, not recreate external effects. Storage failure means reopen, not in-process repair.

## Synthesis decision

Candidate B only. I would take the binding-edition/assignment split, atomic desk crossings, and conditional ref installation as a unit. Dropping any one loses the explanation for why a stale worker, a crash between lanes, or a moving trunk cannot publish the wrong result. No claim to have compared the other runner's candidate.

## Tradeoffs accepted

- We accept immutable entries plus small working documents rather than event-sourcing every keystroke. Reading what is binding is cheap; auditing what was offered is still exact.
- We accept a typed cross-lane switch so the seven fixed stages are code, not a prompt or an extensible engine. Only a change in inter-lane policy needs this file.
- We accept waiting to arm decisions and a last-moment guard because Tau cannot invalidate on raw client admission. A raced host acknowledgement is distinguishable from application of the answer.
- We accept an extra combined verification and a held landing slot rather than claiming that two independently green trees compose. Slow proof affects **landing**, not unrelated design/build work.
- We accept confined file tools and a trusted project check runner rather than pretending that `cwd`, a read-only prompt or an unfiltered shell protects an oracle or a trading account. For a language with colocated signatures/bodies, protect the conformance oracle/scaffold interface separately; don't ban edits to the whole implementation file.
- We accept occasional visible inspection stops on ambiguous partial checkouts, no automatic pruning of witness refs, and no claim of power-failure exactly-once. The contract is process crash/reopen with a surviving store and repo.

## Alternatives considered

- **One supervisor agent holding a project plan and delegating all work.** Hides routing code, exposes every authority, stale-decision and partial-merge distinction to the prompt and anyone editing it. Resolving two concurrent workers' rights then depends on chat history.
- **One event-sourced engine with a generic step graph and effect consumers.** Gives a uniform replay interface, but callers must understand scheduling, correlated signals, historical upcasters and which waiting graph node owns a Git lock. Tau already persists the pending task and atomic commit line. Four fixed receivers hide more with less machinery.
- **Verify the worker branch, then cherry-pick/squash it straight onto current trunk.** A small interface with an untrue guarantee: it hides the very combined tree the verifier needed to see. Retesting after the fact lets an unverified trunk exist.

## Four scenario traces

### 1. Duplicate fee: one item, one failed verdict

1. Host creates designer `W`. Its first authenticated prompt entry `p` anchors `Design.start`. Designer returns `Ground.determined` with the approved fee spec, failing trade and predicate. `DesignExit.edition(E1)` → Build's coordinator edits pending to `[fee]`; `BuildExit.plan-bound` activates E1. No design decision, no arena.
2. `repository.plan(open-build/open-worker)` pins trunk then the build tip. `Build.brief-ready` gives worker A the one-item Encode/test-first assignment; record the red check, seal the check and narrow the fence before the body. A calls `ruling` once; worker doc gains R1 citing the approved booking rule and cost if wrong. `report` → `seal-worker` → `Build.sealed`: S1 is an immutable item-build at H1. The same turn crosses `item-ready` to Verify.
3. A different verifier runs the project checks at H1. One head failure creates block F and failed verdict V1. `VerifyExit.failed` → `Build.rework(fee,V1,[F])`, same worker/tree. A submits S2 at H2, fix addresses F. V2 records F resolved by that fix; there was one failure, not two rounds toward a cap. No need for a second ruling, no queue item or owner stop.
4. Verify integrates H2 against current build head, appends item-record I with both attestations. The coordinator closes its plan (`Closure`). Full-set pass → take trunk in → proof on the single-parent candidate L → install L, release slot. Reviewer trees are removed by journalled leases. Handover cites L and R1. Main unchanged.

### 2. A new seam: two annotation rounds, three riders, three items

1. `Ground.sets-precedent` records missing callers/contradictory docs. Owner-led direction leaves a node “feed contract” to Shape. Its `frame` fixes the question/rubric. `dispatch` allocates candidate A and B on different families. Both complete; judge J records A as base and unasked decisions; synthesis grafts B's cancellation semantics, challenger challenges the probe. `Arena` retains **both** sketches and all reports. The draft has riders r1 evidence-based, r2 incidental, r3 seeded.
2. Round 1 owner chooses revise with two ranges. `acceptAnswer` gets actual annotations; designer returns replies 1 and 2 with D1's ID. Round 2 owner again annotates, selecting B as base; D2 and its numbered replies remain separate. Round 3 re-renders that base, grafts and exact changes, then owner approves the node. `rider` decisions keep r1, drop r2, defer r3 → queue row. Final terms omit r2/r3; any changed binding text is shown again. Edition E2 references all settled rounds; no bulk approve silently defaults three riders.
3. Coordinator proposes goals `contract`, `engine needs contract`, `fixture`. No frozen folders/briefs yet. First item Encode makes the contract and protected probes; only its verified integration opens fan-out. Engine now renders against that head; fixture is independent of engine. Individual pass/commit receipts append one by one under the build slot. One closure and full/combined proof lead to a single trunk commit.

### 3. A wrong seam, not a failing implementation

1. Worker A on item X cites the live signature and its caller in `Queue.file`; investigator reads that finding page, checks duplicates against queue/plan, reproduces the mismatch and returns `wrong-mandate{changes:[order], affected:[X,Z]}` (Z is pending). `QueueExit.hold` makes `Build.pause` revoke X's ticket and block Z in that transaction. ## Open questions and risks

- Does the owner accept the distinction between a host-accepted answer and a Keel-applied answer in the raw-input race? Atomic withdrawal *inside* a stock host `input` call is absent. The witnessed decision contract does not need that new guarantee.
- What project runner already supplies read-only source, ephemeral scratch and no live credentials/network for executable project checks? Which protected tests, money zones, allowed recipes and externally executed actions are approved? Do not offer production check execution until this is established. Building a cross-platform sandbox is **not** estimated or implied by this design.
- Can project policy reserve trunk/private refs for this one Tau project and keep trunk out of foreign checked-out worktrees? Distinct Tau stores have no common landing slot. CAS refuses collisions; it doesn't provide project-wide scheduling across two different stores. Which large artifacts eventually merit owner-authorized retention/GC?
- Which model IDs count as the same family in this installation, what cheap investigator should run, and what sweep cadence is acceptable? Money-path evidence ranks, “same finding” semantics and approved precedent provenance require judgment. Can the owner recognize them from an actual basis without reopening six chats?
- Can the planned closure/witness, confined fence and tool-replay tests pass against real Git/Tau on the owner's platform? The 51-trigger replay, Minos Ground replay and a real rider review have **not** established policy accuracy yet.

**Grounding corrections and scope.** I used `keel-design/grounding.md` as the platform ground truth, cross-checked against Tau core and pi-durable. One narrow correction: pi-durable's `dist/harness/submissions.js:admitSubmission` **does** reject reusing a request ID with a different submission *type*; within the same type it still doesn't compare input text. Also an immediate display-only write is conditional on no queued reset. Neither behavior is a workflow admission guard. The workflow's §7 says “experiment lane” whereas §§6/8 and the task settle three lanes: an experiment is framed work within Shape. “Nothing … in the queue stops the work” describes **filing**; a diagnosed wrong contract/explicit stop holds specific authority, not the queue as a whole. Tau's flat decisions give one choice, not a structured rider form; separate rider decisions and the client mark convention keep this an extension. None of dispatch, the principle section, Git recovery, queue scheduling or check confinement meets the core admission test: workflow-specific policy, composable from an extension/project runner, no two unlike core clients demonstrated to require it. I propose no change to Tau.

## What this design decides that the task did not ask

- A work ID is its design conversation; queue-built work has a new root except an in-place Mandate revision — changing identity later migrates references throughout the store.
- Keep plan/Design/Verify documents on the root, worker notes on workers, and receipts in role/work books — relocating them requires a document migration, not a protocol change.
- Store versioned, immutable pages with display text and content in Tau, not filesystem artifacts, with small mutable pointers — externalizing them later needs a durable reader/retention contract.
- A four-way synchronous crossing function plus ordinary Tau tasks for actual waits/effects, no event replay — replacing it changes transaction boundaries and recovery tests.
- Keep the working doc tokens private and test allowed imports; generate menus/schema from role descriptors — reorganizing modules costs compile-time and policy-test edits, not data migration.
- Use closed role/child selections, a required project model, optional flat lane/seat overrides and explicit family mapping; don't silently substitute an invalid pairing — changing defaults changes future assignments, not existing evidence.
- Anchor authority to the actual actor/input ticket and node set, not a shared work epoch — coarsening it later invalidates more concurrent work and outstanding tickets.
- Arm only after successful idle, witness relevant direct messages, withdraw actively and guard again on answer — removing this costs a weaker stale-answer guarantee or host support.
- Use semantic termination choices, a recommended default that never auto-fires, and no timeouts on owner questions — deadlines would change owner authority and require expiry policy.
- Reserve a nonblocking project decision for marks on arbitrary entries; the client carries their selection in an unranged annotation — replacing this costs one client convention and the intake decoder; it would free one generic inbox row.
- An owner-led direction round may cite the discussion instead of staging a contest — requiring an arena there would change the owner’s direction-setting loop.
- Candidate seats A/B are independently configurable; more seats can be added; judge differs from synthesizer, not necessarily from *every* candidate — changing independence policy changes model requirements and arena acceptance.
- Archive unsuccessful arena attempts; sequential, explicit keep/drop/defer/design rider decisions after node choice, reapprove changed binding text — a form or different sequence needs a new basis/decision reader.
- Carry unchanged node/rider dispositions by content and never silently carry changed ones — invalidating more broadly increases owner rounds, loosening it changes approval semantics.
- A pivot's approved edition waits for the coordinator's pending-only edit; both activate in one store commit — immediate activation without that pairing needs an alternative safe-start rule.
- Replace the ordered pending list by serial CAS; don't freeze briefs or support arbitrary DAG mutations — fine-grained patches would change coordinator tool inputs and conflict handling.
- Allow a one-item repair to narrow one worker from Encode to body; seal protected tests before narrowing — forcing separate workers increases startup/proof cost and changes the one-worker path.
- Use a fenced edit interface and a trusted project check runner instead of general Bash; human applies protected policy changes other than an authorized verification extension — relaxing this requires a different protection/evidence model.
- Ruling cost uses a small ordered severity plus explanation; rank by actual cost category, then stable publication order — changing ranks later requires reinterpreting historical digests.
- A fix counts only with explicit block identity, submission and independent surviving observation; resolved regressions link back — changing identity/counting needs history migration and can alter stops.
- Reuse an integration proof only on the identical commit with identical obligations; otherwise check the combination — broader reuse requires a defensible equivalence rule and new tests.
- Install one-parent squash candidates using private indices/objects, persistent operation witness refs and expected-old Git transactions — another scheme must still distinguish pre/post crash, including subsequently advanced heads.
- FIFO store reservations cover integration through proof and ref install, release on conflict/failure; no time-based lock theft — shortening the reservation requires revalidation/retry under competition.
- Bind one project store per repo/trunk; fixed local trunk ref; refuse a foreign checked-out branch or ambiguous directory, retain witness refs pending retention policy — multi-store coordination, aliases or GC need explicit interoperability/ownership rules.
- Cancellation doesn't revoke an already authorized ref install and Esc isn't workflow cancel — changing this needs a stronger cross-system commit protocol or compensating action.
- Separate queue desk from investigator conversations; route independent determined follow-ups as new builds; don't reopen a landed build — changing this alters triage destinations and closure/history semantics.
- Defer/drop do not release a safety hold that has no lawful continuation; obligations remain owed through defer — changing this is owner policy, not a UI convenience.
- Read project content under protected `.keel/principles/` and `.keel/playbooks/`; qualify colliding packaged/project names instead of overriding silently — moving the paths changes lookup and fences, renaming citations needs aliases for history.
- One weekly sweep starting after the first real project turn, coalesce missed intervals on reopen — changing cadence costs a timer migration, increasing frequency costs investigator time.
- Keep dispatch foreground, all-settled, manifest ordered, with full answers stored even if the tool view is bounded — detached or streaming dispatch changes cancellation, lifetime, and result semantics.
- Source-only extraction of dispatch until a second real consumer earns a shared dependency — extraction entails package/policy wiring but no lane state or registry migration for installed Keel.

# Render verification

Render's own repository verification asset (spec §8.2). Rows prove behavior only when they execute against the actual
source; scaffolding rows (build, lint) prove only what their command claims. Failure cases and their literal expected
outcomes are in `docs/verification/durable-workspace-failure-cases.md`, `docs/verification/durable-role-work-failure-cases.md`, `docs/verification/context-policy-continuity-failure-cases.md` and `docs/verification/github-publication-failure-cases.md`.

## Ranks

Strongest first. Render's ladder replaces the generic tests → build → inspection fallback.

1. `process`: real host subprocesses, a real SQLite store on disk and real HTTP/Unix-socket transports, driven by
   independent clients.
2. `tests`: in-process executable oracles at a module interface (pure Kernel, Ledger over real SQLite).
3. `build`: typecheck and lint.
4. `inspection`: cited source inspection. Architectural commitments only; never a behavioral pass.

## Launch

- Install: `npm ci --ignore-scripts` (exact pins in `package-lock.json`).
- Own instance only. Every check starts its own host with `node src/host/main.ts serve --data <fresh temp dir> --port 0`
  and reads the `ready` line from stdout for the URL and admin socket. Never point a check at a live data directory.
- Enroll check devices through the admin socket of that instance (`node src/client/cli.ts admin enroll ...`).

## Doctor

- Node `24.21.0` (`node --version`), npm 11. Native `.ts` execution; no build step.
- macOS `hdiutil` for the real disk-full case (`B2-09`). Elsewhere that case reports `skipped: hdiutil unavailable`,
  not passed.
- Write access to the OS temp directory. Loopback TCP must be available.
- Owned-source rows additionally require Git 2.43+, a real Docker Linux runtime, and a local `node:24-alpine` fixture
  image (resolved to its immutable ID in each run). Missing prerequisites fail visibly; they are not skipped into a pass.
  See `docs/owned-checks.md` for ordinary-network and execution-time workspace-write limits (separate issue #39, not a slice gate).

## Selections

A file's suffix chooses its selection, and `test:full` runs all three suffixes once, so a test cannot fall out of the cumulative gate. Put a new test in `*.test.ts` only when it needs no container, load, repeated fault or disk image.

| Command | Runs | Establishes | Does not establish |
|---|---|---|---|
| `npm test` | `test/*.test.ts`, eight file workers | Fast functional feedback: pure Kernel, in-process role/policy/continuation/web journeys on real SQLite, literal HTTP command cases, Git-only source refusals. Needs no Docker. | Any cumulative, process-fault, container, load or extended result. Never report it as the full suite. |
| `npm run test:integration` | `test/*.integration.ts`, serial | Host processes, crash barriers, repeated interruption, real disk-full, V2 sampled schedules, containers. | Load bounds or extended counts. |
| `npm run test:performance` | `test/*.performance.ts`, serial | Latency and saturation workloads, including the full V9 workload. Run nothing else alongside them. | The V9 time budgets (`verify:v9-budgets`). |
| `npm run test:full` | `npm test`, then `test:integration`, then `test:performance`: each suffix once, stopping at the first failing selection. Fast tests use their eight file workers; containers, processes and latency stay serial, with nothing alongside them. | The `full-suite` row. | Typecheck, lint, extended counts, unsafe controls. |
| `npm run verify:gate` | typecheck, lint, `test:full` | The Full Gate on the checked-out source. Stops at the first failing command; later commands then have no result. | Extended counts, unsafe controls. |
| `npm run test:extended` | `test:extended:host` (V2 256, history load, V3 100 for commands, tools, web, investigation and implementation handoff/successor), then `test:extended:containers` (V3 100 for source root, owned check, cancellation, sealed experiment results, prepared-X checks, Watchdog checks and canonical integration) | Separately measured extended jobs. Not interchangeable with smoke. | |
| `npm run verify:unsafe-controls` | Every named mutation | Each targeted check rejects its wrong behavior. | |
| `npm run verify:complete` | `verify:gate`, `test:extended`, `verify:v9-budgets`, `verify:unsafe-controls` | Everything above on the checked-out source. | |

The named `verify:*` rows below select by behavior and overlap each other and `test:full`. While iterating, run the union of the affected files once with `node --test <files>`. A result belongs to the source it ran on: after any source, dependency or target change, the applicable gate runs again. Implementer and Watchdog verification are independent; neither reuses the other's or an earlier source's result. A missing prerequisite fails or reports `skipped`, and neither counts as a pass.

Run the broader selection when a change touches its guarantee: `test:integration` for startup, durability, transport, processes or containers; `test:performance` for commit, observe or snapshot paths; the matching extended job for a crash barrier. Failure cases and retained measurements for this split are in `docs/verification/fast-developer-feedback-failure-cases.md`; source-specific results belong in implementation/review reports, with raw output outside source.

Raw logs and diagnostic scratch belong outside the source tree. Existing workflow reports retain exact source, commands, outcomes, timings and limits. `evidence/` is neither required nor recreated.

2. Run `policy-adoption`: publish future defaults, adopt selected revision with expected binding, reject stale adoption, adopt back without reviving old basis or resetting completed reviews.

4. Run `task-version-recovery`: stop writers, refuse incompatible definitions and preserve uncertainty; reopen the same store with its compatible executable without rewriting task meaning. This does not test backup restoration.

## Cleanup

Every check removes its temp data directories, kills the host processes it started (SIGKILL after a 2 s grace period),
and detaches any disk image it attached (`hdiutil detach -force`). A leftover `/Volumes`-less mount named
`render-full-*` under the temp directory is from an interrupted `B2-09` run and is safe to detach.

## Traps

- `RENDER_FAULT_BARRIER=<before-commit|after-commit|before-source-root|after-source-root|after-sandbox-stop>` with `RENDER_FAULT_COMMAND=<commandId>` makes the host announce
  `{"event":"barrier"}` on stdout and stop at that point so a check can SIGKILL it. It is inert unless set; never set it
  outside checks.
- `fullfsync` makes each commit wait for the device cache flush. Expect several milliseconds per commit on macOS. This wait, shared across file workers, is most of the `npm test` wall time, so more workers stop helping beyond about four.
- Do not inspect, copy or run skl tests.
- Never point a check at the user's live data directory or a live Render host.
